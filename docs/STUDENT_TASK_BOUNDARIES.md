# 本科生功能开发边界（2–3 人）

| 角色 | 模块 | 建议题目 | 验收指标 |
| --- | --- | --- | --- |
| 学生 A | Web + Backend + AI 诊断策略 | 基于多源信息融合的作物病虫害辅助诊断研究 | 图像/症状联合诊断，与纯图像方法对比准确率、召回率、耗时 |
| 学生 B | React Native | 面向田间弱网环境的移动端病虫害检测研究 | 拍照、缓存、失败重试、断网恢复；记录成功率、完成时间、流量 |
| 可选学生 C | Backend + Web 管理 | 基于专家反馈的病虫害诊断优化系统设计 | 样本审核、纠错记录、版本追踪、权限测试 |

维护者统一负责 Git 仓库、接口规范、评审、CI、部署、安全整改和上线审批，不把“只调用现有 AI 接口”当作毕业设计主要工作量。

分支约定：`feat/multisource-*`、`feat/mobile-field-*`、`feat/feedback-*`；每项功能都需要 Issue、PR、测试数据和真实 Git 提交记录，禁止直接未经评审修改 main。
